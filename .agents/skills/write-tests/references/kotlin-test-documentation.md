# Kotlin 테스트 문서화

이 문서는 write-tests의 참고 자료다. 상위 스킬을 다시 읽도록 요구하지 않는다. 새 테스트와 수정한 테스트에 적용하며, 관련 없는 테스트를 일괄 문서화하지 않는다.

## 목적과 상세 수준

- 테스트 이름만으로 의도가 충분하지 않으면 한국어 KDoc으로 계약·이유를 보완한다. 단순 테스트는 목적과 기대 결과를 짧게 적는다.
- 동시성·취소·재시도·상태 전이처럼 실행 조건이 중요한 테스트는 다음 네 항목을 KDoc에 명시한다.
  - 테스트 목적: 검증할 동작·불변식과 의미.
  - 테스트 조건: 초기 상태·입력·Fake/Mock·실패 또는 동시성 조건.
  - 테스트 절차: dispatcher·gate·취소/예외 시점·실행 순서·대기 완료 조건 중 실제 사용하는 것.
  - 기대 결과: 실제 assertion 또는 mock 검증으로 확인하는 관찰값. 예상 예외 판정에 의존하면 그 방식도 설명한다.
- 클래스 KDoc은 공통 계약이나 결함 참조를 설명할 필요가 있을 때 작성한다. 모든 메서드 설명을 중복하지 않는다.

## 정확성

테스트 본문과 대역을 읽고 실제 검증 내용을 설명한다. 로그 출력이나 예외 없이 종료된 사실을 상태·호출 횟수 assertion처럼 설명하지 않는다.

요구사항·목적·assertion 사이의 불일치나 검증 누락은 파일·함수·근거와 함께 별도로 보고한다. 불명확한 요구사항은 결함으로 단정하지 않는다. 유효한 기존 계약·문서·결함 참조는 보존한다.

문서화 중 문제를 발견했다고 테스트 로직·assertion·제품 코드를 임의로 바꾸지 않는다. KDoc 안의 경로·glob 등에서 블록 주석 시작 토큰을 쓰지 않도록 주의해 중첩 주석 문법 오류를 피한다.

## 실행 로그

모든 테스트에 로그를 추가하지 않는다. 실행 흐름 추적이 필요한 동시성·비동기·취소·상태 전이 테스트에만 검토한다. 로그는 assertion이나 gate를 대신하지 않는다.

추가하면 단계·주요 상태를 표시하되 실제 금융 데이터·토큰·키·인증정보를 출력하지 않는다. 문서화 전용 작업에서는 로그를 추가하지 않고 필요한 위치·이유만 보고한다.
