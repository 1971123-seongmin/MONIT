# Learning Log

MONIT 실습·학습 기록을 한국어로 작성한다. PM이 운영 기준을 관리하며 이 스킬은 요청된 날짜의 근거 수집·중복 확인·기록·검증을 담당한다. 일일 예약 실행이나 다른 역할 채팅으로의 자동 전달을 활성화하지 않는다.

## 대상과 범위

- 공통 AGENTS.md와 [운영 기준](../../../docs/ai/learning-log.md)을 읽는다. 문서에 연결된 MONIT 팀스페이스·대시보드·데이터 소스를 확인하고 개인 영역에 대신 저장하지 않는다.
- 기본 날짜는 Asia/Seoul의 오늘이다. 날짜를 지정하면 그 날짜를 따른다. 자정을 넘긴 대화의 모든 작업을 오늘 수행한 것으로 옮기지 않는다. 실행 일시가 불명확하면 이전 작업 검토 또는 날짜 미확인으로 표시한다.
- 기록 요청은 해당 일자의 생성·갱신에 적용한다. 검토·초안만 요청했거나 사용자가 승인 후 저장을 요구했다면 내용을 먼저 제시하고 저장하지 않는다. DB·스키마·상위 위치 변경은 기존 승인 범위를 확인한다.

## 근거 수집과 중복 방지

1. 현재 작업 기록과 `git status`, 대상 날짜의 `git log`, 관련 diff·실제 검증 결과를 확인한다. 다른 채팅은 관련성이 있고 접근 가능한 경우에만 읽으며 전체 대화를 반복 수집하지 않는다.
2. 커밋 시각은 작업 수행일의 증거가 아니다. 미커밋·로컬 커밋·원격 push·PR 등록·병합을 구분한다. 원격에 없는 커밋은 해시로 표시하고 사용 가능한 GitHub 링크라고 쓰지 않는다.
3. 지정 데이터 소스에서 학습일로 기존 기록을 찾는다. 같은 날짜는 기존 페이지를 보완하며 여러 건이면 내용을 비교해 갱신 대상을 정하고 임의 삭제하지 않는다. 새 근거가 없으면 중복 내용을 추가하지 않는다.
4. 같은 사실의 원본이 Issue·PR·ADR·협업 로그에 있으면 학습 관점의 짧은 요약과 링크만 남긴다. 비밀정보·실제 금융 데이터·인증 출력은 기록하지 않는다.

## 작성과 검증

- 제목은 `YYYY-MM-DD · 핵심 학습 주제`, 속성은 제목·학습일·주제를 사용한다.
- 본문은 날짜 및 학습 주제, 오늘의 목표, 실제 수행한 작업, 학습한 개념과 핵심 원리, 발생한 문제와 해결 방법, 주요 의사결정 및 선택 이유, 검증 결과와 참고 링크, 다음에 학습할 내용 중 해당 항목만 작성한다.
- 완료 작업에는 확인 근거를 연결한다. 개념 이해는 제품 구현 완료로 표현하지 않는다. 원인이 확정되지 않은 오류는 관찰된 증상·가설·확인 결과를 구분한다. 실패·미실행·승인 대기는 그대로 적는다.
- 관련 공식 자료는 필요한 경우만 조회한다. 기술 명세와 코드 사본을 Notion에 독립 관리하지 않는다.
- Notion 도구의 현재 스키마를 따르고 일부 갱신을 우선한다. 성공 응답·재조회로 parent, 날짜, 속성과 핵심 내용의 반영을 확인한다. 응답이 불명확하면 다시 조회한 후 재시도해 중복 생성을 막는다.
- 결과는 기록 링크, 신규/갱신 여부, 확인한 근거와 남은 한계만 간결하게 보고한다. 기록을 위해 커밋·push·PR 생성·설정 변경을 자동 수행하지 않는다.
