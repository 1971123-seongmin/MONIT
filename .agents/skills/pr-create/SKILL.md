# PR Create

MONIT PR의 제목과 본문을 실제 변경 및 검증 결과에 맞춰 작성한다. 제목 형식과 승인 경계는 루트 AGENTS.md를, 본문 구조는 `.github/pull_request_template.md`를 기준으로 한다. 템플릿을 스킬 안에 복제하지 않는다.

## 변경과 이슈 확인

- Git 루트와 origin이 `1971123-seongmin/MONIT`인지 확인한다. 인증정보가 포함된 URL은 출력하지 않는다. 다른 저장소나 전역 설정을 변경하지 않는다.
- 현재 브랜치, 작업 트리, 실제 base/head와 해당 차이 및 커밋을 확인한다. base를 무조건 main으로 가정하지 않는다. 미커밋 변경은 PR diff에 포함된 것으로 설명하지 않는다.
- 관련 이슈의 실제 번호·내용과 기존 PR 유무를 확인한다. 같은 head의 PR이 있으면 새 PR을 중복 생성하지 않고 요청에 따라 기존 PR을 갱신한다.
- 관련 이슈가 없으면 번호를 만들거나 임의로 이슈를 생성하지 않는다. 제목을 확정하기 위해 필요한 정보만 확인하고, 그동안 본문 초안을 준비한다.

## 제목과 본문 작성

- 제목은 AGENTS.md의 `[KEYWORD/#이슈번호] 이슈명 또는 적절한 문장/단어` 형식으로 작성한다. 예: `[FEAT/#3] 홈 화면 구현`. 커밋 메시지 형식을 PR 제목에 적용하지 않는다.
- 템플릿의 항목을 유지하면서 변경 목적과 최종 동작을 먼저 설명한다. 주요 변경 사항은 리뷰에 필요한 내용으로 채우고 대화 이력이나 폐기한 접근은 필요한 경우만 설명한다.
- `Closes #번호`는 실제로 해결한 관련 이슈에만 쓴다. 일부 진행이나 참고용 이슈는 `Refs #번호` 등으로 연결한다. 빈 `Closes #`는 남기지 않는다.
- 테스트 체크박스는 실제 수행한 검증으로만 체크한다. 실행 명령·결과와 미실행 사유를 구분하고, 문서 변경처럼 해당하지 않는 검증은 해당 없음으로 설명한다. CI나 CodeRabbit 결과를 확인하지 않았다면 완료로 쓰지 않는다.
- UI 변경은 확인 가능한 스크린샷을 사용한다. 없으면 미첨부 사유를 적고 이미지나 성공 결과를 만들어내지 않는다. 공개 PR에 비밀정보·개인 금융 데이터·로컬 인증정보를 포함하지 않는다.
- 선택 항목의 빈 예시는 불필요하면 없음으로 정리한다. 미완료 작업과 실제 제한은 숨기지 않는다.

## 등록과 결과 확인

- 초안 작성 요청은 초안 제공까지 수행한다. GitHub PR 생성·수정 요청은 해당 작업의 승인으로 적용하되, 작성만 요청한 것을 원격 등록 승인으로 확대하지 않는다. 이미 받은 승인은 다시 묻지 않는다.
- 커밋과 push는 별도로 승인된 범위에서만 수행한다. 미커밋 작업이 있다는 이유로 자동 커밋하거나 강제 push하지 않는다. PR 병합·배포·저장소 설정 변경은 수행하지 않는다.
- 원격 작업 전에 제목·본문·base/head를 확인한다. GitHub CLI를 사용하면 항상 `--repo 1971123-seongmin/MONIT`를 지정하고, 여러 줄 본문은 UTF-8 임시 파일과 `--body-file`로 전달한다. 충분한 MCP 기능이 있으면 우선 사용한다.
- 생성 요청이 실패하거나 응답이 불명확하면 기존 PR을 다시 조회해 실제 생성 여부를 확인한 뒤 재시도한다. 무작정 중복 생성하지 않는다.
- 생성한 PR은 `attach_artifact` 도구가 제공되면 현재 채팅에 연결한다. 사용자가 기존 PR의 갱신을 요청한 경우에도 연결한다.
- 원격 제목·본문·base/head와 URL을 재조회해 확인하고 결과를 보고한다. 초안만 작성했거나 검증이 제한되었다면 그 범위를 명시한다.
