# 개발 학습 기록 운영

PM은 기록의 위치·형식·중복 방지·근거 기준을 관리한다. 실제 작성은 [learning-log 스킬](../../.agents/skills/learning-log/SKILL.md)을 사용한다. 자연어 학습 기록 요청 또는 `$learning-log` 명시 호출로 적용하며 예약 실행은 구성하지 않는다.

## 위치와 구조

- MONIT 팀스페이스: `4072e2ce-2fe6-817b-906c-004252dfff15`.
- 상위: [MONIT · Project Dashboard](https://app.notion.com/p/4072e2ce2fe6817c9fbad344f4a902be).
- 기록: [Dev Learning Log](https://app.notion.com/p/71a22c9beab54383b5971bf05ba4ab27).
- 데이터 소스: `collection://5cbfe9f1-d79b-4ec0-adfe-f745cb92f1bf`.
- 속성: `제목`(Title), `학습일`(Date), `주제`(Multi-select). 최신 학습은 날짜 내림차순 표, 학습 달력은 학습일 기준이다.
- 날짜는 Asia/Seoul 기준이며 날짜당 한 페이지를 유지한다. 같은 날 재실행하면 새로운 근거만 반영한다. 별도 상태 속성으로 작업 완료를 추정하지 않는다.

## 기록 원칙

본문은 날짜 및 학습 주제, 오늘의 목표, 실제 수행한 작업, 학습한 개념과 핵심 원리, 발생한 문제와 해결 방법, 주요 의사결정 및 선택 이유, 검증 결과와 참고 링크, 다음에 학습할 내용 순서로 필요한 항목만 작성한다.

실제 수행 결과와 개념 학습을 구분한다. 실행하지 않은 검사는 통과로 기록하지 않으며 미확인 원인은 가설로 표시한다. 과거 작업을 오늘 검토했다면 그 사실을 적는다. 로컬 커밋·push·PR·병합·배포를 각각 확인하고 공개 원격에 없는 커밋 링크를 만들어내지 않는다.

코드·기술 계약·Migration·ADR의 원본은 Git이다. Notion에는 배운 원리·선택 이유·시행착오와 원본 링크만 정리한다. 협업 로그는 역할 간 요청·결정, 학습 로그는 개인 실습에서 얻은 이해와 재현 가능한 교훈을 담는다. 같은 상세 설명을 두 DB에 복사하지 않는다.

접근 권한·위치·기존 날짜 기록을 먼저 확인한다. 대화 전체·저장소 전체·외부 문서를 매번 재조회하지 않고 관련 변경과 검증 근거만 읽는다. 실제 금융 데이터·인증정보는 저장하지 않는다.
