## 책임과 입력

계좌 탭에서 feature:accounts의 별도 Nav2 미리보기로 진입한다. 사용자가 선택한 content URI를 잠시 읽으며 원본 파일 복사·영속 URI 권한·Notion 조회/수정·Room 쓰기를 하지 않는다. 기존 Hilt·CoroutineContextProvider·기본 viewModelScope를 사용한다. 파일 I/O는 io, UTF-8/JSON/digest 검사와 투영은 default에서 실행하고 취소를 전파한다.

형식은 일반 CSV나 Notion REST 응답 자동 변환이 아닌 명시적인 검토 JSON v1이다. envelope의 snapshotJson/mappingJson은 정확한 UTF-8 문자열이며 각각의 SHA256을 검증한다. 전체 입력 bytes의 digest도 따로 유지한다. snapshot은 추출 시각/범위·출처별 pagination/미확보 속성·행의 출처/종류/원본 ID 또는 locator·정확한 rawJson/digest·관계 확보 상태를 포함한다. namespace는 원본 데이터소스의 안정적인 출처이며 파일명·연도 제목으로 추론하지 않는다.

mapping은 version/transformerVersion·대상 ledgerId/storageGeneration·명시적인 원본 속성명/Wallet 출처·확인한 통화/계좌 대응·보류/제외 결정을 포함한다. 원문은 정해진 평면 속성 타입만 해석한다. 미지원 구조·환전·카드 정산·관계 누락/복수·통화/계좌 미확인은 보류한다. won 표시·카드명·연결 계좌·초기자산·수식 잔액으로 통화/계좌/확인 잔액을 추정하지 않는다.

대상 null/누락은 원문·보류 미리보기만 허용하며 다른 confirmed 필드가 있어도 금융 후보0을 유지한다. 명시한 다른 장부/세대는 파일 차단이고 현재 context/revision을 승인 매핑으로 채워 넣지 않는다. 이 준비 상태를 데이터 없음·지원 불가·이관 완료로 표시하지 않는다.

원문·관계·원본 키·digest와 매핑 version은 결과의 행 근거로 남긴다. 원본 ID가 없으면 snapshot digest와 locator로 해당 추출본에서만 추적하며, 재내보낸 파일이나 행 순서가 다른 파일까지 같은 원본으로 확정하지 않는다. 원문 해시는 진위 인증이나 거래 유일성의 근거가 아니다.

## 판정과 표시

원본 행은 반영예정 후보/기반영/보류/제외 중 하나다. 유사 중복·반복 원본 키·관계 누락·미지원 등 여러 사유가 있어도 보류 한 행으로만 집계한다. 현재 schema3에는 source mapping이 없으므로 기반영은 0, 중복 검증은 확인 불가다. 날짜/금액/계좌가 같은 로컬 거래는 보류 후보이며 자동 병합·삭제하지 않는다.

반영예정은 필요한 필드·명시 매핑을 검사한 변환 후보이며 신규 확정·중복 없음·실제 반영 승인이 아니다. 원본 행 수와 예상 생성 거래 수를 구분한다. 이체는 하나의 행에 출금/입금 관계가 명시된 경우만 후보로 만들고, 두 행을 짝맞추거나 카드 정산으로 추정하지 않는다. 이체 쌍 정규화의 별도 계약이 없는 입력은 보류한다.

출처/종류별 원본 수, 네 판정별 수, 통화·종류별 금액, 미확보 범위, 알려진 계좌 효과와 대사 한계를 보여 준다. pagination/속성 미확보는 부분 추출이며 알려진 행 수가 Notion 전체 수라는 의미가 아니다. 파일 해석 실패로 행 경계를 모르면 행 수는 0이 아닌 확인 불가다. 예상 합계·계좌 효과는 지원 후보에 한정하며 수식 잔액이나 전체 금액 대사 성공으로 표현하지 않는다.

화면은 원본/mapping digest·version·읽은 ledger revision에 결합한 변경 감지 지문을 유지한다. 실제 반영 승인 토큰은 아니다. 로컬 revision을 다시 확인해 달라졌으면 기존 결과를 최신으로 표시하지 않고 재검토를 요구한다. 다른 원본/매핑 선택도 새 검토다. 실제 생성 거래 수는 항상 0이며 반영 버튼/API를 제공하지 않는다.

## 검증과 제외

합성 fixtures의 정상/파일 손상/digest/UTF-8/중복 키/행 관계/반복 원본/유사 로컬 기록/부분 pagination/금액·종류 합계와 원문 보존을 검사한다. ViewModel의 읽기 전용 호출·취소/늦은 응답·다른 장부·revision 변경, 실제 파일 선택 어댑터와 Compose 목록/큰 글꼴·Back을 관련 계층에서 확인한다. 실제 원본 미리보기·추출 완전성·실제 금액 대사와 구분한다.

입력 JSON의 상세 필드/제한과 합성 예시는 [검토 JSON v1](../contracts/import-preview-v1.md)에서 관리한다. 문서·README는 자동 포매팅하지 않는다. Room3→4·이관 배치 원자 writer·source mapping 저장·실제 금융 반영·원본 변경·백업 복원은 이번 단계에 포함하지 않는다. 실제 반영은 사용자에게 미리보기를 보여 준 뒤 별도 구체안 승인으로 진행한다.
